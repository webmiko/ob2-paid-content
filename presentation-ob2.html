Слайд 2а–б · Проблема

Проблема рынка

Авторы — преподаватели, эксперты, креаторы — продают контент кустарно: мессенджеры, облачные диски, Excel-списки. Доступ к платным материалам выдаётся вручную. Нет единого paywall — барьера, который отображает заглушку до оплаты.

Боли бизнеса
  • Ручная работа съедает до 40% времени автора
  • Выручка теряется, контент утекает
  • Отсутствует API для подключения собственного сайта
Цель Creavity Автоматизировать монетизацию: один вход, оплата картой, мгновенный доступ без участия автора.

Слайд 2в · Рынок

Рыночный контекст и аналоги

На рынке есть инструменты монетизации, но нет единой платформы с одной подпиской на всех авторов.

Зарубежные аналоги
  • Patreon, Boosty, Buy Me a Coffee — подписка на отдельного автора
  • Medium — прямой аналог Creavity: $5/мес открывает всех авторов
Российские аналоги
  • Boosty Pro (499 ₽) — не все авторы, нет сквозного paywall
  • VK Donut, Дзен — закрытые экосистемы, нет API
  • Полного аналога «одна подписка — весь premium» нет

Creavity = Netflix/Medium для авторов: один платёж → все paid; paywall через can_view_post_body. Ниша: СНГ-платформа с универсальной подпиской и открытым API.

Слайд 3а · Концепция

Концепция решения

Python + Django 6 + Django REST Framework (DRF) — REST API, JSON · React 19 (Vite) — SPA (одностраничное приложение) · PostgreSQL 16 (база данных).

Логика доступа: бесплатный пост открыт всем; платный — автору безусловно, остальным только при активной подписке. Один алгоритм в API и шаблонах. 

# posts/services/access.py
def can_view_post_body(user, post, *, subscription_active=None):
    if not post.is_paid: return True
    if user is None or user.is_anonymous: return False
    if post.author_id == user.pk: return True
    if subscription_active is not None: return subscription_active
    return user_has_active_subscription(user)

Уровни доступа — на слайде 3в (без отдельной таблицы прав в БД).

Слайд 3в · Концепция

Три уровня доступа

Роли вычисляются при каждом запросе — не поле в профиле и не таблица прав.

Гость Видит бесплатное; платное закрыто paywall — заголовок и кнопка оплаты.
Зарегистрированный пользователь JWT-токен; CRUD своих постов. Свой платный пост видит всегда.
Подписчик После оплаты через Stripe — все paid-материалы всех авторов одной подпиской.

Единая подписка Creavity (~990 ₽) · не подписка на отдельного автора.

Слайд 4а · Техника

Техническая архитектура

Бэкенд (сервер) Django + DRF (REST Framework) + Simple JWT (токены) · Stripe Checkout Почему: «батарейки в комплекте» — ORM, админка, готовый REST
Фронтенд (клиент) React 19 + Vite · PWA (прогрессивное веб-приложение) Почему: динамичный UI, один JSON API на все клиенты
Прокси nginx — раздаёт статику и перенаправляет API-запросы → Django Почему: одна точка для статики, /api и лимита запросов
Инфраструктура PostgreSQL 16 · GitHub Actions (CI/CD) → Docker → продакшн Почему: надёжные транзакции оплат (не SQLite) + автодеплой

REST API — доступ к данным через HTTP в формате JSON. CRUD — базовые операции: Create (создать), Read (читать), Update (обновить), Delete (удалить). Документация — Swagger на /api/docs/. Роли и схема БД — слайд 4в.

class PostViewSet(viewsets.ModelViewSet):
    permission_classes = (IsAuthorOrReadOnly,)

Слайд 4б · Техника

Архитектура

Поток данных: приложение (SPA) → nginx → Django ViewSet → сервисный слой → ORM → PostgreSQL. Оплата: пользователь → Stripe → возврат на сайт → activate_subscription() (можно вызвать повторно). Доступ проверяется через can_view_post_body(), а не через таблицу прав.

Клиент SPA и прокси nginx — тот же монорепозиторий

Слайд 4в · Техника

ORM: схема БД и роли

Django ORM · PostgreSQL 16 · без raw SQL. Paywall — в API, не в отдельной таблице прав.

Роли (вычисляются при запросе, не поле в БД)
Роль Доступ
Guest free-посты; paid — paywall
User CRUD своих постов; paid чужих — скрыт
Subscriber все paid всех авторов после Stripe
Author свои paid видит всегда (без подписки)
Архитектурные решения
  • can_view_post_body() — paywall в API, не в таблице прав
  • AUTH_USER_MODEL — вход по телефону, не username
  • Один PENDING payment на пользователя (constraint)
  • activate_subscription() — повторный вызов безопасен после оплаты
  • Admin: Forms + Templates (теги OB2)

Слайд 7 · Бизнес-ценность

Бизнес-ценность

Допущение: 100 активных подписчиков в месяц и отраслевые ориентиры.

Экономия времени До 40% времени авторов — администрирование. Ручной процесс: ~9 мин/подписчик. Автоматизация −80% → ~15 ч/мес.
Рост конверсии Единая платёжная страница вместо переписки. UX-исследования (Baymard): упрощение чекаута +20–35%. Консервативно: +25%.
Рыночная цена Подписка 990 ₽ — верхняя граница российского рынка, но отражает ценность «единый доступ ко всем авторам».
Готовность к запуску Stripe работает на боевом сервере, сценарий «оплата → подписка → доступ» проверен. Можно запускать пилот сразу — нулевое время выхода на рынок.
