Слайд 2а · Проблема

Бизнес- и пользовательская боль

Независимые авторы публикуют контент в разрозненных каналах без единого paywall и контроля доступа к paid-материалам.

Как сейчас Ручная выдача доступа, Excel, ссылки «для своих», нет прозрачной оплаты и защиты контента.
Последствия Потеря выручки, утечки материалов, высокие операционные затраты на поддержку подписчиков.

Слайд 3а · Концепция

Что делает продукт

Монорепозиторий: JSON API + React SPA + PostgreSQL.

Роль не выбирается в профиле: guest / user / sub / author — автоматически по входу, оплате и авторству поста.

  • Публикации free/paid с единым paywall
  • Регистрация по телефону, JWT для SPA и REST API
  • Stripe Checkout → разовая подписка → все paid-посты
  • CRUD постов; опубликовал — ты автор своих paid
Guest не вошёл · free да · paid — paywall
User login · CRUD · свои paid видит всегда
Sub после Stripe · все paid всех авторов

Слайд 3в · Концепция

Paywall и win-win модель

Paywall — «стена доступа»: free-посты видны всем, paid — только после разовой подписки на платформу (не на автора). Проверка в API: can_view_post_body().

Одна подписка Creavity → все paid-материалы всех авторов. Все стороны в выигрыше:

Читатель (guest) Бесплатные материалы без регистрации; понятная воронка «попробовал free → захотел premium».
Подписчик Один платёж (~990 ₽) и Stripe Checkout — доступ ко всем авторам, без десятка разрозненных ссылок и паролей.
Автор Free — витрина, paid — эксклюзив; аудитория, комментарии, статистика; свой Stripe не нужен. Свои paid-посты видит всегда.
Платформа Creavity Единый paywall и монетизация; больше premium-контента — сильнее ценность подписки. v2: выплаты авторам (Stripe Connect).

Roadmap Creavity

Куда развивать продукт
  • Stripe webhook + Celery — надёжная активация без redirect
  • Stripe Connect — выплаты авторам, доля платформы

  • HTTPS + домен, мониторинг, масштабирование web/worker
  • Аналитика MAU, конверсия, модерация, mobile-клиент
Уже заложено в v1
  • Monorepo: JSON API + SPA — новые клиенты без смены backend
  • services/: activate_subscription(), can_view_post_body(), stripe
  • Idempotent activate — webhook подключится без второго алгоритма
  • config/constants + .env — сумма, JWT, Stripe без правок views
  • Docker + CI/CD + PWA; JWT permissions; 147 тестов, 89.78%

Принцип: новая фича → сервис + тест; v2 не ломает v1 (DRY, один paywall, один activate).
